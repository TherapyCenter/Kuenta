      About this translationKuenta is built for workshops in Germany: tax, e-invoicing, cash register (TSE) and DATEV follow German law. This handbook uses the menu names of the English user interface. German terms such as HU (the German MOT), TSE or GoBD are kept where they refer to German rules.

      What is Kuenta?

      Kuenta is invoicing software for car workshops. You use it to write quotes, orders and invoices, manage customers and vehicles, run the cash register and the stock, and create e-invoices.

      Kuenta is a web application: a small program runs in the background on the workshop PC (the Kuenta server). You use Kuenta in the browser, on the same PC or on tablets and other workstations in the network. Screens and workflow follow KFZ-Faktura, whose data Kuenta takes over completely.

      Good to knowThe console window is the Kuenta server. It must stay open while Kuenta is in use. Closing it stops Kuenta.

      Installation

      After installation the database is empty. How to enter your company details and take over existing data is described in First setup and Taking over data.

      Windows 10 / 11 (64 bit)

      1. Run Kuenta-Setup-1.8.2.exe.Node.js is included in the installer, nothing else needs to be installed.
      2. Choose the installation type.For all users (default, needs administrator rights) installs to C:\Program Files\Kuenta. Only for me needs no administrator rights and installs into the user profile.
      3. Choose options.Desktop shortcut and, for network mode, the firewall rule (only when installing for all users).
      4. Start:Start menu Kuenta. The console window opens, and the browser opens http://127.0.0.1:3700.

      The installer speaks English, German or Spanish and picks the language of Windows. The start menu has three entries: Kuenta (this PC only), Kuenta (network) (for tablets and other workstations) and Uninstall Kuenta. With the German installer they are called Kuenta, Kuenta im Netzwerk and Kuenta deinstallieren.

      A new installation starts in the language of Windows (German, Spanish, otherwise English). The console window uses the same language. To switch the user interface, use the menu Kuenta → Sprache / Language or the language box on the login page.

      Container (Docker / Podman)

      For Linux servers, NAS systems, Raspberry Pi or Macs, Kuenta also runs in a container. The image includes Node.js and runs on x86_64 and ARM64. The Kuenta folder contains a Dockerfile and a compose.yaml for this.

      # Podman (for Docker replace podman with docker)
podman build -t kuenta:1.8.2 .
podman run -d --name kuenta --restart unless-stopped \
  -p 3700:3700 -v kuenta-daten:/data kuenta:1.8.2

# or with Compose
docker compose up -d --build

      Then open http://<computer>:3700 in the browser.

      Switch on loginIn a container Kuenta can be reached from the whole network. Switch on login right after the first start (Settings → Defaults). For this computer only: -p 127.0.0.1:3700:3700.
      TopicIn the container
      Datain the volume kuenta-daten (/data in the container). It is kept when the container is rebuilt. Own folder: -v /srv/kuenta:/data; it must belong to UID 1000. With rootless Podman append :Z,U.
      Backupsalso mount a folder from the NAS, e.g. -v /mnt/nas/kuenta-sicherungen:/sicherungen, and enter /sicherungen as the backup folder in Kuenta.
      Time zonedefault Europe/Berlin, change with -e TZ=Europe/Madrid.
      Emaildirect sending via SMTP only. Handing over to Thunderbird is not available in the container.
      KFZ-Faktura importupload the backup *.kfz or DB1.bak. The direct import from the program folder is only available on Windows.
      Stoppodman stop kuenta closes the database cleanly.
      Updatebuild the image with the new version, remove the container with podman rm -f kuenta and create it again with the new image. The data in the volume is kept.

      Automatic start with Podman via a Quadlet file and more details: see INSTALL.md, section "Container".

      First setup

      After the first start, the overview shows buttons for the setup. The most important points:

      2. Tax, dunning, registerVAT rates, small business rule, dunning levels with days and fees, opening cash balance.
      3. Number rangesEach field holds the last number used. The next invoice gets this number plus 1. If numbering should start at a certain number, e.g. at the beginning of the year, enter the number before it. More under Invoice numbers.

      5. Users and loginCreate users under Master data → Users / employees, tick "Login allowed" and switch on login under Settings → Defaults. This is required in network mode.

      From KFZ-Faktura

      1. Backup *.kfz: in KFZ-Faktura use "Daten sichern", then upload the file in Kuenta (drag and drop). Password-protected backups are supported.
      2. Database backup DB1.bak or *.fbk: upload directly.
      3. Program folder (Windows only), e.g. C:\KFZ-Faktura. Close KFZ-Faktura first. The original database is only copied, never changed.

      All tables are taken over: customers, vehicles, articles, labour items, suppliers, tyre storage, all documents, payments, open items, dunning letters, cash book, accounting entries, text modules, settings, number ranges, KBA vehicle codes and the postcode directory, plus documents, images and the company logo.

      Importing again: what is kept, what is replaced

      You can import KFZ-Faktura data more than once, e.g. during a transition period. Before the import Kuenta shows an overview:

      is kept

      Data that only exists in Kuenta

      • settings: email, register, TSE, backup, printing
      • register receipts and closings
      • time tracking, appointments, tasks, letters
      • incoming invoices, vehicle trading, purchase contracts, down payments
      • documents uploaded in Kuenta, email and change log
      • Kuenta's own fields in master data, e.g. e-invoice format and Leitweg ID of the customer, IBAN of the supplier, target hours of employees
      is replaced

      Data from KFZ-Faktura

      • customers, vehicles, articles, labour items, suppliers
      • quotes, orders, delivery notes, invoices
      • payments, cash book, number ranges

      Beforehand Kuenta tells you how many of these records were created or changed in Kuenta since the last import. They are replaced by the state from the backup.

      With the tick "Keep Kuenta's own data" (default) the above applies. Without the tick the import replaces everything with the backup.

      Safety copyBefore every import Kuenta saves a copy of the previous data in the subfolder sicherheitskopien of the data folder.
      Working in parallelDo not work on the same invoices in KFZ-Faktura and Kuenta at the same time. Invoices you write in Kuenta (also automatically at the register) are overwritten by the next import.
      7-Zip backupsNewer KFZ-Faktura versions pack the .kfz file in 7-Zip format. In that case unpack the file with 7-Zip and upload db\DB1.bak.

      CSV and DATANORM

      The import assistant takes over customers, vehicles, articles, labour items and suppliers from CSV files. Columns are mapped to Kuenta fields, and the mapping can be saved as a template. Article data from wholesalers comes via DATANORM 4/5.

      Overview: hiding amounts and switching currency

      At the top right of the overview there are two switches. Both apply only to the current workstation.

      SwitchEffect
      👁 Eyehides all amounts on the overview with asterisks, e.g. when customers can see the screen. Click again to show them.
      € · $ · £ · CHF · ₿shows the amounts in euros, US dollars, pounds sterling, Swiss francs or bitcoin at the current rate. Another click on ₿ switches to satoshis (1 bitcoin = 100,000,000 sats) and back. The button remembers the unit used last. Rate and source are shown below the tiles.
      Display onlyInvoices, payments, bookings, DATEV and all printouts always stay in the company's currency (euros, pounds in the UK, dollars in the US, francs in Switzerland). The switch only changes how the figures are shown on the overview.

      The rates come from the European Central Bank (US dollar, pound sterling and Swiss franc, reference rate of the last banking day) and from the Bitstamp exchange (bitcoin, current rate).

      InternetFor the rates the Kuenta computer asks the ECB and Bitstamp, at most every three hours. No data from Kuenta is sent. Kuenta caches the rates. Without internet the last loaded rates apply. If no rates were ever loaded, the display stays in euros.

      Colours

      Under Settings → Defaults → Appearance you set two things:

      • Colour scheme: light, dark or automatic as in the operating system.
      • Colour: blue (default), green, graphite or bordeaux. Each colour exists in light and dark.

      Both apply only to the current workstation or browser. This way the register, the tablet in the workshop or a demo company can be told apart at a glance.

      Language

      The user interface and documents are available in German, English, Spanish, French, Italian and Dutch. There are two settings:

      • Language of the user interface: in the menu Kuenta → Sprache / Language, on the login page or under Settings → Defaults. It applies only to the current workstation. In English, numbers appear as 1,234.50 and dates as 31/12/2026.
      • Language of documents: under Settings → Defaults. It applies to the whole company and affects PDF documents, printing, dunning letters and the templates for emails and reminders. You can choose German, English, Spanish, Italian, Dutch and French.

      What you enter yourself stays as it is: article texts, customer names and your own text templates are not translated. Legal notes such as § 19 UStG appear translated, but the law of the chosen tax system still applies; the legal texts of the other countries (France, Italy, Netherlands, Belgium) are printed in the national language. The e-invoice (XRechnung) stays in German.

      E-invoice

      Kuenta creates e-invoices according to EN 16931 and reads incoming e-invoices.

      FormatDescription
      XRechnung 3.0 (CII)pure XML file, e.g. for public authorities
      XRechnung 3.0 (UBL)pure XML file in UBL syntax
      ZUGFeRD 2.3 / Factur-XPDF/A-3 with embedded XRechnung, readable by people and software
      Factur-X EN 16931France: PDF with embedded CII, also for Chorus Pro
      FatturaPA 1.2.2Italy: XML for the SdI (consumers, businesses, public bodies)
      ebInterface 6.1Austria: XML for e-rechnung.gv.at
      Peppol BIS Billing 3.0Netherlands, Belgium and Luxembourg: UBL through the Peppol network
      QR-billSwitzerland: payment part with Swiss QR Code on the invoice

      Which format a customer gets is set in their e-invoice settings. It is suggested automatically when sending by email. Supported tax cases: reverse charge, intra-community supply, export, small business, margin scheme. Checked with the Mustang validator, against the EN 16931 rules and the KoSIT XRechnung rules (3.0.2); FatturaPA, ebInterface, Peppol and the Belgian VAT return against the official schemas and rules.

      Read incoming e-invoices under Purchasing → Incoming invoice. To view an XRechnung use Purchasing → Visualise e-invoice.

      Spain: IVA and VERI*FACTU

      Kuenta can work with Spanish tax law per company. Switch it under Settings → Tax / dunning / register → Tax system (the settings are in the tab Spain / VERI*FACTU), then save and reload the program. For Spanish documents set the document language to Español under Settings → Defaults → Language. Other companies, existing invoices, backups and the import from KFZ-Faktura stay unchanged.

      What changes

      • IVA: 21 %, 10 % and 4 % (adjustable), exempt items and suplidos (amounts paid on behalf of the customer, e.g. the ITV fee; enter them as pass-through items).
      • Recargo de equivalencia: switch it on in the customer under Tax & accounting. The surcharge (5.2 / 1.4 / 0.5 %) is added to the invoice automatically.
      • NIF: in the customer in the field VAT ID / NIF. Your own NIF goes into Company details → Tax number.
      • Invoice numbers: series + consecutive number, e.g. F20260001; corrective invoices use the series R.
      • Invoice types: customers with a NIF get a full invoice (F1), others a simplified invoice (F2) up to 400 €. Above that Kuenta asks for the NIF.
      • Register: every sale is an invoice; the receipt shows series, number, NIF and the QR code. VERI*FACTU replaces the TSE.
      • Accounting: Finance → FIBU export offers the books facturas expedidas and recibidas as CSV and an overview for the modelo 303.
      • E-invoice for public administrations: Facturae 3.2.2. Enter the DIR3 codes of the administration in the customer's Leitweg ID field as Office/Body/Unit. Sign the file with AutoFirma before uploading it to FACe.

      VERI*FACTU

      An invoice is issued as soon as it leaves Kuenta: print, PDF, email or register. Kuenta asks first. A record with hash chain is created, and its QR code is printed at the top of the invoice. Kuenta sends the record to the AEAT, or automatically later when there is no internet. From then on the invoice is locked; corrections only by a corrective invoice (cancel invoice). The status is shown in the invoice window next to the buttons.

      1. Store the company's electronic certificate (.p12 / .pfx) under Settings → Spain / VERI*FACTU and test the connection.
      2. Issue some invoices in the Test environment and check that they are accepted. Best use a separate test company, because test invoices stay locked as well.
      3. Switch to Production. From now on the invoices are registered with the AEAT.

      Certificate, hash chain and a copy of all records are in the data folder under verifactu. This folder is not part of the Kuenta backup and is kept when a backup is restored, so no record is lost and no reported number is used twice. Please back up this folder as well.

      Not supported: TicketBAI (Basque Country), Navarre, IGIC (Canary Islands), margin scheme (REBU) in VERI*FACTU, the "No VERI*FACTU" mode and SII.

      United Kingdom: VAT and Making Tax Digital

      Choose "United Kingdom" under Settings → Tax / dunning / register → Tax system, save and reload. The company then works in pounds (£). Enter your VAT number under Company details → VAT ID (e.g. GB123456782) and set the document language to English.

      • Invoices are titled "VAT invoice" and show the tax point, the VAT rate of each line and your VAT Reg. No. Corrections are titled "Credit note".
      • Rates: standard (20 %), reduced (5 %), zero rate, exempt. Enter disbursements such as the MOT fee as pass-through items (outside the scope). Used cars with margin taxation use the second-hand margin scheme.
      • Not VAT registered: below the threshold tick "Not VAT registered" – invoices then carry no VAT.
      • Scheme: standard, cash accounting (VAT when paid) or flat rate scheme (rate adjustable, vehicle repair 8.5 %).

      VAT return through Making Tax Digital

      1. Once: store the HMRC Developer Hub credentials (Settings → United Kingdom / MTD), then Connect to HMRC and sign in with the business's Government Gateway account. The connection lasts 18 months.
      2. Finance → FIBU export: Load periods from HMRC, then Calculate & submit for the open period.
      3. Check the 9 boxes, confirm the declaration and submit. HMRC replies with a receipt (form bundle number).

      Boxes 1 and 6 come from the invoices, boxes 4 and 7 from the purchase invoices. For testing use the HMRC sandbox. Sign-in data is kept in the data folder under gb, not in the backup.

      The same page offers CSV exports for Xero (sales invoices and bills), QuickBooks Online, Sage 50 and a VAT journal.

      United States: sales tax

      Choose "United States" under Settings → Tax / dunning / register → Tax system, save and reload. The company then works in dollars and dates are written month first (MM/DD/YYYY). Enter the town as "Springfield, IL" and the ZIP code in the postcode field.

      • Sales tax: enter the combined rate of your location (state + county + city) under Settings → United States / Sales tax. Whether labor, shop supplies and fees are taxable differs by state and is adjustable. Taxable lines carry a "T" on the invoice.
      • Tax-exempt customers (resale, government, non-profit): in the customer under Tax & accounting with the exemption certificate number.
      • Invoice requirements: the shop's registration number in the footer, condition of parts (new, used, rebuilt) on the line, odometer in and out, what happened to replaced parts (tab Other).
      • Shop supplies and fees: buttons in the line toolbar. Shop supplies are a percentage of labor with a maximum; fees (hazardous waste, tires per tire, core charge) are a list in the settings.
      • Estimate authorization: record every authorization of the customer with amount, date, method and person in the tab Other. It is printed on the order and invoice; if the invoice is above it, Kuenta asks before printing. The estimate carries the notice and a signature line.
      • Register: prices before tax; the sales tax is added to the total.
      • Accounting: Finance → FIBU export creates a CSV for the invoice import into QuickBooks Online (tax code TAX/NON).

      Kuenta does not look up rates automatically and does not file returns; your accountant or QuickBooks does that.

      France: VAT, Factur-X and cash register (NF525)

      Choose “France” under Settings → Tax / dunning / register → Tax system, save and reload. The settings are on the tab France. For French documents choose the document language “Français”.

      • Company data: SIRET (14 digits) into Tax number, VAT number (FR…) into VAT ID. Legal form, capital, RCS and APE code on the tab France; they appear in the footer.
      • Rates: 20 % (full VAT), 10 % (reduced VAT), 5.5 % (code “AT-MwSt”), 0 % exempt. The franchise en base (art. 293 B CGI) can be switched on.
      • Mandatory notes: nature of the operations, discount, late payment penalties and the € 40 recovery fee for business customers are printed automatically; the SIREN/SIRET of business customers goes into the customer. Printed invoices are locked; corrections are credit notes (avoir).
      • Factur-X: in the invoice window Factur-X / Chorus Pro → download Factur-X PDF (profile EN 16931). Invoices to public bodies go directly to Chorus Pro (PISTE credentials on the tab France).
      • Cash register: every receipt is signed and chained to the previous one, with grand totals, daily, monthly and yearly closures, numbered duplicates and an event log. The journal is also kept outside the backup and stays complete when an older backup is restored. The NF525 certification is done by an accredited body.
      • Accounting: Finance → FIBU export creates the FEC and the signed cash register archive and lists the Chorus Pro deposits.

      Austria: VAT, cash register (RKSV) and UVA

      Choose “Österreich” under Settings → Tax / dunning / register → Tax system, save and reload. The settings are on the tab Österreich.

      • Company data: the UID number (ATU…) goes into VAT ID, the tax number (tax office + number, 9 digits) into Tax number. Legal form, seat, company register number and court on the tab Österreich (§ 14 UGB).
      • Rates: 20 % (full VAT), 10 % (reduced VAT), 13 % (third rate, code “AT-MwSt”), exempt 0 %. Small business exemption and cash accounting can be switched on.
      • Invoices: UID of the company, date of supply and, above € 10,000 gross, the UID of the customer. E-invoice → Check mandatory fields lists anything missing.
      • E-invoices to the federal government: E-invoice (ebInterface) → download ebInterface 6.1 and upload it at e-rechnung.gv.at. The supplier number goes into the customer's Leitweg-ID field, the order reference into the invoice's order number.

      Cash register (RKSV)

      1. On the tab Österreich enter the cash register ID and choose the signature device: A-Trust a.sign RK (user name and password from A-Trust) or the trial mode with a local key. The trial mode is not RKSV compliant.
      2. Activate cash register: Kuenta creates the AES key and the start receipt. Register the cash register ID and the AES key in FinanzOnline and check the start receipt with the BMF receipt check app.
      3. Every sale and cancellation at the register gets a signed receipt with QR code. At the change of month Kuenta creates the monthly receipt, in December the yearly receipt. Check the yearly receipt and keep it.
      4. If the signature device fails, receipts read “Sicherheitseinrichtung ausgefallen”, followed by a collective receipt once it works again. Report failures longer than 48 hours in FinanzOnline.

      Finance → FIBU export (view “Steuer (Österreich)”) lists all RKSV receipts, checks chain, turnover counter and signatures and exports the data collection protocol (DEP).

      VAT return (UVA)

      The same view calculates the UVA (Kennzahlen 000, 011, 017, 016, 020, 022, 029, 006, 060) and creates the XML file for the upload in FinanzOnline (U30). Report services to EU businesses and intra-community supplies in the recapitulative statement as well.

      Switzerland: VAT, QR-bill and CHF

      Choose “Schweiz” under Settings → Tax / dunning / register → Tax system, save and reload. The company then works in francs (CHF 1'234.50). The settings are on the tab Schweiz.

      DATEV export for the tax adviser

      Kuenta books invoices, payments, incoming invoices and register sales automatically and exports them as DATEV files. Your tax adviser reads them directly into DATEV, the accounting software common in Germany.

      Set up once

      Under Settings → Accounting. Your tax adviser gives you the values.

      SettingMeaning
      Adviser number, client numberyour numbers at the DATEV firm
      General ledger account lengthusually 4. Also determines the personal accounts (see below)
      Fiscal year starts in month1 = calendar year. For a different fiscal year the start month, e.g. 7 for 01.07.–30.06.
      Collective debtoraccount for customers without their own debtor account (default 10000)
      Collective creditorunder Settings → Purchasing / trading (default 70000)
      Include BU keysonly switch on if your tax adviser uses revenue and expense accounts without the automatic function. Revenue then gets the VAT key (19 %: 3, 7 %: 2), incoming invoices the input tax key (19 %: 9, 7 %: 8).
      Accountscash, bank and revenue accounts (SKR03 default). For SKR04 please agree with your tax adviser and adjust.

      Personal accounts (debtors and creditors)

      Personal accounts have one digit more than general ledger accounts. With account length 4:

      KindRangeWhere the number comes from
      Debtors (customers)10000–69999debtor no. of the customer, otherwise customer number, otherwise collective debtor
      Creditors (suppliers)70000–99999creditor no. of the supplier, otherwise supplier number, otherwise collective creditor

      A number outside the range, e.g. supplier no. 3 from a KFZ-Faktura import, is not used, because it would be a general ledger account. The booking then goes to the collective account. If the customer should get an account of their own, enter the debtor no. for the customer or the creditor no. for the supplier.

      Monthly routine

      1. Choose the periodFinance → Accounting export, e.g. the previous month. The list shows all bookings not yet exported.
      2. Export debtors/creditorsThe file EXTF_Debitoren_Kreditoren_….csv contains name, address, country and VAT ID of all customers and suppliers with bookings in the period. That way the tax adviser sees names instead of just account numbers.
      3. Create the DATEV exportThe file EXTF_Buchungsstapel_….csv contains the bookings. Kuenta marks them as exported so they do not come twice next time. "Preview export" creates the same file without marking.
      4. Send to the tax adviserBoth files. The adviser reads the debtors/creditors first, then the booking batch.
      Please note One export may only cover one fiscal year. Export December and January separately. Kuenta points this out. The invoices as PDF are not included. The tax adviser still gets the documents separately. The first time, have your tax adviser read both files as a test (booking batch and debtors/creditors) and check the accounts. Bookings already saved keep their accounts. If bookings were made earlier for a customer or supplier with a short number (below 10000 or 70000), the booking may be on a general ledger account. The export cannot detect this, because e.g. "3" is a valid general ledger account. Enter a debtor or creditor no. for such customers and suppliers and have older bookings checked by the tax adviser.

      The files are saved in the Windows-1252 character set, as DATEV expects. Umlauts therefore arrive correctly.

      Crypto payment: Bitcoin, Lightning, USDT

      Customers can pay invoices with Bitcoin, Lightning or USDT. Kuenta uses your own BTCPay Server for this. It is free open source software that holds no money: payments go directly into your own wallet. The feature is included in Kuenta free of charge.

      Set up once

      1. Provide a BTCPay ServerThe server must be reachable from the internet so customers can pay. Usual is a rented server with the official Docker setup (docs.btcpayserver.org) or a provider that runs BTCPay. Create a store there and connect your wallet. For Lightning you need a Lightning node, for USDT the Liquid network.
      2. Create an API keyIn BTCPay under Account → API keys. Required rights: view and modify payment requests, view, create and modify invoices, view store settings. The store ID is shown in the store settings.
      3. Enter it in KuentaSettings → Crypto payment: enable crypto payments, enter address, store ID and API key, then "Save & test connection". Kuenta shows the payment methods active in the store.
      4. Clarify the accountingKuenta books incoming payments to the configured accounting account, default 1360 (money in transit, SKR03). Agree the account with your tax adviser.

      How a payment works

      • Open the invoice, tab Payments, "Payment link". Kuenta creates a payment page at BTCPay for the open euro amount. It is valid for 30 days (adjustable).
      • QR code and link then appear automatically on the PDF invoice and in the email. In your own email templates {Zahlungslink} inserts the link.
      • The customer pays the euro amount in Bitcoin, Lightning or USDT, converted at the rate on the day of payment.
      • Kuenta checks with BTCPay every 2 minutes and books paid invoices automatically, with the payment type "Krypto (BTCPay)". "Check for payment" does it immediately.
      • If the open amount changes, e.g. after a partial payment by bank transfer, the old link disappears from the PDF. Create a new one then. If the invoice is paid in full some other way, Kuenta closes the payment page at BTCPay.

      Kuenta does not need to be reachable from the internet for this. It asks BTCPay itself.

      At the register

      • Once crypto payment is set up, the register shows the button "₿ Bitcoin / Lightning". "Pay order" and "Pay invoice" then offer "Crypto" too.
      • The register shows a QR code, first for Lightning, on request for Bitcoin or USDT. The customer scans it with their wallet. The rate is fixed for 15 minutes.
      • As soon as BTCPay reports the payment, the window closes and the receipt is printed. Bitcoin on-chain counts as soon as the payment is in the network, without waiting for a confirmation. Lightning arrives within seconds.
      • Kuenta verifies the payment with BTCPay itself before the receipt. Only then are invoice and receipt created. Each payment can only be used for one receipt.
      • Cancel: Kuenta marks the payment as invalid at BTCPay. For this the API key also needs the right "modify invoices". Without it the payment expires after 15 minutes. If the customer still pays, the register shows a notice when opened. Refund the amount via BTCPay then.
      • Void: Kuenta books the refund. Refund the money in BTCPay with the "Refund" function on the invoice, or in cash.
      • Crypto payments are non-cash. They do not go into the cash book, the TSE signs them as non-cash, and in the DSFinV-K export they appear as "Unbar / Krypto".

      Backup and data folder

      The data is never in the program folder but in the user profile. Updates leave it untouched; when uninstalling you decide whether to keep it.

      SystemData folder
      Windows%APPDATA%\Kuenta (e.g. C:\Users\<name>\AppData\Roaming\Kuenta)
      macOS~/Library/Application Support/Kuenta
      Linux~/.local/share/kuenta

      Among other things, the data folder contains the database kuenta.db, documents and images (dateien), automatic backups (sicherungen), safety copies before imports (sicherheitskopien) and the attachments for the mail program (mail-ausgang).

      Backing up

      • By hand: Kuenta → Back up data creates a *.kuenta file with database and documents. With a password it is AES-256 encrypted.
      • Automatically: Kuenta backs up daily into the folder sicherungen. Folder and number of backups kept (default 14) are set on the same page.
      • Whole folder: alternatively copy the complete data folder while Kuenta is stopped.
      RecommendationPut the backup folder on another drive, a NAS or a USB stick. A backup on the same hard disk does not help if that disk fails.
      Do not put the data folder on a network driveBackups belong on the NAS, the data folder itself does not. Kuenta works in its database all the time. Over a network share it can get damaged, e.g. during a short network outage. If the data folder is on a network drive, Kuenta warns at start. For several workstations use network mode: one computer holds the data, all others work in the browser.

      Updating and rolling out

      To update, simply run the new installer. It does everything itself:

      1. Find a running KuentaThe installer looks for Kuenta processes from the program folder, including the console window.
      2. Stop cleanlyKuenta is asked to stop and closes the database properly. If it does not respond, it is killed.
      3. Install the updateProgram files are replaced. The data in the user profile stays unchanged.
      4. Start againKuenta starts in the same mode as before (local or network). A new tab opens in the browser.

      Rolling out without questions

      For scripts or software distribution:

      SwitchEffect

      /SUPPRESSMSGBOXESno questions

      Linux / macOS: get the new version (git pull or archive) and run ./installer/unix/install.sh again.

      • Windows: Settings → Apps → Kuenta or start menu Uninstall Kuenta. A running Kuenta is stopped first and the firewall rule removed.
      • Linux / macOS: ./installer/unix/install.sh --uninstall

      On Windows you can also start the installer again: if Kuenta is already installed it offers to update or to uninstall.

      Afterwards Kuenta asks whether to delete the data too. The default is keep the data. If you delete it, you can save a copy first: on Windows as a ZIP on the desktop, on Linux/macOS as a .tar.gz in the home folder. If the copy fails, nothing is deleted. Keep the retention periods in mind: invoices and cash register data usually have to be kept for up to 10 years.

      Invoice numbers

      Invoice numbers are sequential, as in KFZ-Faktura. Kuenta assigns the number itself when saving: last number used plus 1. The invoice number field is therefore locked. For a new invoice it only shows a suggestion. If another workstation saves an invoice first, your invoice gets the next free number.

      • Separate number ranges: invoices and invoice corrections (including cancellations and credit notes) are counted separately. The settings are under Settings → Number ranges.
      • After importing from KFZ-Faktura Kuenta continues from the last number used.
      • No restart at the turn of the year: the numbers simply continue. A new database starts at year + 0001, e.g. 20260001.

      How gaps can occur

      • Unprinted invoice deleted: the number is not assigned again. Write down the reason so you can explain the gap in an audit. Better: do not delete the invoice, cancel it.
      • Number range raised by hand: entering a higher number under Settings → Number ranges skips the numbers in between.

      Printed or sent invoices cannot be deleted, only cancelled. The cancellation invoice gets a number from the range of invoice corrections.

      Notes and limits

      • TSE: the cloud TSE from fiskaly (SIGN DE) is supported. Check with a fiskaly test account before going live and register the register with the tax office. USB TSEs and the Austrian RKSV are not supported.
      • Card terminal: ZVT over TCP/IP has been tested against a simulated terminal, not against a real device.
      • DSFinV-K: check with the DSFinV-K test tool before an audit.
      • Parts catalogues: live connections to TecDoc, DAT or Elekat need manufacturer licenses and are not included. Shopping carts are taken over as CSV/DATANORM.
      • Purchase contract: the contract texts are a template and do not replace legal advice.
      • DATEV: booking batch and debtors/creditors follow the DATEV format but have not been cross-checked in a DATEV program. Documents (PDF) and a connection to DATEV Unternehmen online are not included.
      • Crypto payment: tested against a simulated BTCPay Server, not yet against a real one. USDT only works via the Liquid network, as offered by BTCPay. USDT on Tron or Ethereum is not supported.
      • Container: the image has so far only been checked outside a real Docker or Podman environment.
      • Database: Kuenta uses a built-in database (SQLite). An external database such as PostgreSQL is not supported. Several workstations work via network mode.
      • Countries and languages: Germany, Spain, the United Kingdom and the United States (switchable per company). Not supported in Spain: TicketBAI, Navarre, IGIC and REBU in VERI*FACTU; in the UK: Northern Ireland EU trade. The interface is available in German, English, Spanish, French, Italian and Dutch.

      Development and installer

      npm test                    # automated tests
npm run server              # start the server without a browser
npm run installer:windows   # build the Windows installer

      The installer needs Windows, Inno Setup 6 and internet access (Node.js is downloaded from nodejs.org and verified with SHA-256). The result is in build\Kuenta-Setup-<version>.exe; the version comes from package.json.

      Structure: server/ (server, business logic, import, e-invoice, PDF/A, email, register, backup), public/ (user interface), installer/ (Windows installer, Linux/macOS script). The database is SQLite with the table and column names of KFZ-Faktura. Code comments are in English. Translations of the interface are in public/js/lang/; node tools/i18n/missing.js lists missing ones. Customer and company data never belongs in the repository.
